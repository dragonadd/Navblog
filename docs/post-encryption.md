# 文章密码加密

正文在后台浏览器内使用原生 Web Crypto 加密，再通过 Git API 提交，无需服务器。

## 使用

1. 写文章或编辑普通文章，勾选“文章密码加密”。填写至少 4 个字符的密码，并确认密码。后台登录密码的 8 位字母数字规则不受影响。
2. 填写允许公开的标题、摘要、分类、标签和封面。摘要留空会显示“本文已加密，请输入密码阅读。”，不会自动从私密正文截取。
3. 保存后，Git 中的 Markdown 保留公开 front matter，正文是 JSON 密文封装。部署完成后访客输入密码解锁。
4. 再次编辑加密文章时必须先解锁，才能编辑、重新加密或关闭加密。密码框留空沿用当前解锁密码；填写并确认新密码可换密码。
5. 关闭加密后保存会公开完整正文。文章正文和密码不会自动保存在浏览器存储；刷新页面需要重新解锁。后台本地演示和导出也只保存密文。

密码请自行妥善保管，丢失后无法恢复正文。运行环境需要 HTTPS 或 localhost。

不要把密码写进文章标题、摘要或标签：这些信息会公开出现在首页、搜索、RSS 和分享中。演示文章的测试密码可单独告知体验者，真实加密文章应通过私下渠道提供密码。

## 数据格式和出口

元数据使用 `encrypted: true`，不要手写 `password` 等明文密码字段，也不要只给明文文章添加加密标记。

密文封装固定 v1，AES-256-GCM（128 位认证标签），PBKDF2-SHA-256（600,000 次）。每次保存重新生成 16 字节 salt 和 12 字节 IV，认证附加数据为 `navblog-encrypted:v1`。密钥不可导出，密码不进入 Git 或部署设置。

构建前严格验证标记、算法版本和密文结构。格式错误、缺少加密标记、标记加密但仍是明文、元数据中出现密码字段时停止构建；不会回退发布明文。元数据解析错误也停止读取。

| 出口 | 加密文章行为 |
| --- | --- |
| Git Markdown / `content/posts/*.md` | 公开元数据及密文正文 |
| 文章索引、首页、分类、标签、搜索 | 标题及公开摘要；不包含私密正文和密文片段 |
| 文章静态 HTML / SEO / JSON-LD | 公开元数据和解锁提示 |
| RSS | 保留条目、公开摘要及文章链接，不包含私密全文或密文；普通文章仍为全文 |
| 浏览器解锁 | 验证密码后解密、渲染 Markdown 并建立目录；重新锁定、刷新或离开页面移除已渲染正文 |
| 评论 | 加密文章解锁后按现有评论设置显示 |

该功能保护正文。标题、摘要、分类、标签、封面、公开图床附件和外部评论仍公开。已经在公开仓库提交过的明文历史不因重新加密而消失。静态密文可被离线尝试密码，应使用较长且独有的口令。
