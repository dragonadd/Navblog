# 后台双模式登录与登录密码

## 登录

登录页每次请求 `data/auth.json?t=<当前时间戳>`，使用 `cache: no-store`、不携带浏览器 Cookie，并设 8 秒超时。

- 文件不存在（404/204）或空白：只提供 Git Token 登录。
- 有合法密文：默认“密码登录”，可以切换“Token 登录”作为忘记密码或 Token 已过期的兜底。
- 网络失败、HTML 回退或损坏密文：提示重试，同时提供 Token 登录；不会把异常冒充“未设置”。

两种方式取得的 Token 都校验 Git 用户及目标仓库权限。GitHub/Gitee 检查仓库 `permissions.push`，GitLab 检查项目/组角色；归档仓库不允许登录。读取权限信息不能证明 Token 的全部 scope、分支保护或图片分支限制已满足，真实写入仍由 Git 平台最终校验。

## 会话存储

Token 只保存在当前标签页的 `sessionStorage`，同时供运行时内存请求使用，不写入 `localStorage`。键按部署子路径、平台、主机、仓库、分支和 GitLab 项目 ID 隔离。升级会清除旧 `localStorage.token`，不会迁移旧 Token，需重新登录。退出登录清除当前会话。

页面刷新可保留登录。通常关闭标签页会清除，但复制标签页、浏览器恢复会话等可能继承存储，不能保证关闭即不可恢复。需要明确清理时请点击退出登录。密码和派生密钥不保存到浏览器存储。

## 设置、修改和移除

在 **站点设置 → 登录密码管理**，填写“新登录密码”和“确认登录密码”。规则：至少 **8 个字符**且包含字母和数字；不合格或确认不一致时提示红字并禁用保存。为了安全性，建议使用 **12 位以上的独有密码**，最好更长。

密码只参与 PBKDF2-SHA-256（600,000 次）派生密钥；加密内容仅为当前会话的 Token。AES-256-GCM 每次使用新的 16 字节 salt 和 12 字节 IV，128 位认证标签。密钥不可导出。凭证采用独立 `navblog-auth` v1 格式，与文章加密格式分开，认证附加数据绑定上述 Git 仓库身份。

提交的 `data/auth.json` 只包含格式、版本、算法、迭代次数、salt、IV 和密文，不包含明文 Token、密码、密码副本或派生密钥。它通过现有 Git API 单独提交，不随普通站点设置一起保存。写入或删除携带读取时的文件版本，发生冲突提示刷新，不覆盖另一窗口的更新。

“移除密码”需页内确认，删除仓库中的 `data/auth.json`。提交成功提示：已提交，正在部署，请等待 1–2 分钟；部署成功后刷新页面生效。提交成功不等于部署已成功，时间戳也不能绕过尚未完成的部署。

本地演示模式不管理真实登录凭证；需要退出演示并使用 Token 登录。演示导出不包含当前会话 Token。单元测试使用测试凭证和内存 Git API，不提交真实凭证。

## 静态部署

`prepare` 严格验证原始文件，输出经校验的密文到 `src/generated/auth/auth.json`；Angular 开发及生产构建都在 `data/auth.json` 路径提供文件。文件为空/移除后不生成资源，`postbuild` 会清理旧输出。

该文件不并入设置、文章索引、搜索、RSS 或预渲染正文。Netlify/Cloudflare 的 `_headers` 设置该路径 `Cache-Control: no-store`；登录请求仍带时间戳，其他 CDN 是否忽略查询参数需按实际部署核对。

## 保护边界

这是密码解锁 Git 写入凭证的便利入口，不是独立服务器账号系统。公开密文可以下载后离线猜解，前端重试限制不能阻止这种攻击。

删除或换密码不会消除 Git 历史、旧部署和已下载的密文，也不会撤销其中的 Token。需要撤销旧密码访问能力时，先在 Git 平台撤销/轮换专用 Token，再用新 Token 登录、重新设置密码。建议只授权博客仓库、设置到期时间，并保留 Token 兜底。

`sessionStorage` 无法抵挡同源恶意脚本。自定义脚本、head HTML 和所有能在页面执行的代码都应可信；密码管理及登录使用 HTTPS 或 localhost。不要把真实 Token 粘到正文、普通设置、日志或演示文件中。

## 验证命令

- `pnpm exec tsx scripts/test-admin-auth.ts`：密码规则、加密隔离、会话迁移/取消/存储受限。
- `pnpm exec tsx scripts/test-auth-service.ts`：请求防缓存、错误分支、设置和移除密文。
- `pnpm exec tsx scripts/test-auth-ui.ts`：默认 Tab、统一校验、密码强度及提交失败提示。
- `pnpm exec tsx scripts/test-auth-build.ts`：临时测试密文构建、公开输出无 Token/密码、明文拒绝、移除后清理；结束后恢复正式构建。

文章加密仍要求至少 12 位密码，本轮 8 位规则仅针对后台登录密码。
